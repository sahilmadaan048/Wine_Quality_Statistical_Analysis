# 1. First: What does "regression" mean in machine learning?

In machine learning, we usually have:

\[
X \rightarrow y
\]

where:

- \(X\) = input/features
- \(y\) = target/output we want to predict

The type of problem depends mainly on **what kind of output we are trying to predict**.

There are two major possibilities:

### Classification

Predict a **category/class**.

Example:

```text
Input → Email
Output → Spam / Not Spam
```

or:

```text
Input → Patient information
Output → Disease / No Disease
```

The output is a class.

---

### Regression

Predict a **numerical value**.

Example:

```text
Input → House features
Output → ₹75 lakh
```

or:

```text
Input → Temperature, humidity, etc.
Output → Tomorrow's temperature = 31.5°C
```

The output is a number.

# 8. This connects directly to our MAE

Our Random Forest obtained:

\[
MAE = 0.4931
\]

What does this mean?

MAE is:

\[
MAE =
\frac{1}{n}
\sum |y_i-\hat y_i|
\]

In simple language:

> On average, our predicted quality differs from the actual quality by about **0.49 quality points**.

This makes sense because we're predicting a **number**.

If this were classification, we'd instead typically talk about things like:

- accuracy
- precision
- recall
- F1-score

But our project doesn't use those.

---

# 9. This also explains RMSE

Our Random Forest got:

\[
RMSE=0.6440
\]

RMSE is based on squared prediction errors:

\[
RMSE =
\sqrt{
\frac{1}{n}
\sum(y_i-\hat y_i)^2
}
\]

Again, this only makes sense because we're evaluating **numerical prediction errors**.

For example:

```text
Actual = 6
Predicted = 5.5
Error = 0.5
```

versus:

```text
Actual = 6
Predicted = 3
Error = 3
```

The second error is much worse.

---

# 10. And this explains why we use R²

We obtained:

\[
R^2=0.3853
\]

R² is a regression metric.

It tells us approximately how much variation in the numerical target is explained by the model relative to a baseline.

So when we say:

> Random Forest has \(R^2=0.3853\),

we're talking about its ability to explain variation in the **numerical quality score**.

It does **not** mean:

> "38.53% accuracy."

That's a very important distinction for your viva.

# 16. One subtle point your professor may raise

A smart professor could say:

> "But wine quality is technically an ordinal variable. Why are you treating it as continuous?"

This is actually a **very good question**.

Quality scores:

```text
3 < 4 < 5 < 6 < 7 < 8
```

are ordered.

So quality is naturally an **ordinal** measurement.

However, in this project we chose to treat the quality score numerically so that we could model the **score itself** using regression.

This is a modeling choice.

It allows us to ask:

> "How close is our predicted quality score to the actual quality score?"

rather than simply asking:

> "Did we predict the exact category correctly?"

The report's methodology reflects exactly this choice by evaluating the models using regression metrics: MAE, MSE, RMSE and R². Wine_Quality_Statistical_Analys…
